Изменения API ТТН из Мириады (мобильное приложение)
====================================================
Ветка: develop
Эндпоинт (без изменений URL):
  GET /api/ttn/miriada/current/

Авторизация не требуется (AllowAny), как и раньше.
При запросе сервер синхронизирует список из Мириады и отдаёт
локальные записи за последние 5 дней.


1. Новые поля в ответе
----------------------
Раньше:
  {
    "ttn_id": 56615,
    "name": "0567005",
    "auto": "AH 8918-1",
    "date": "2026-10-16"
  }

Сейчас:
  {
    "ttn_id": 56615,
    "name": "0567005",
    "auto": "AH 8918-1",
    "operation_name": "Отпуск в ПУ/РГС",
    "date": "2026-10-16",
    "status": 1
  }

operation_name — название операции из Мириады (строка, может быть "").
status — числовой enum (только чтение, в запросе не передавать):
  1 = не обрабатывалась
  2 = ошибка при обработке
  3 = закрыта


2. Как меняется status
----------------------
Статус ведёт сервер, не Мириада и не клиент:
  - при получении/синхронизации списка: новые ТТН → status=1
  - успешное закрытие ТТН (closettn при завершении партии) → status=3
  - ошибка закрытия ТТН → status=2

Повторная синхронизация списка не сбрасывает уже выставленный status.


3. Что сделать в приложении
---------------------------
1. Распарсить новые поля operation_name и status.
2. Показать пользователю тип операции (operation_name).
3. Отобразить статус ТТН по числовому enum (1/2/3).
4. Старые поля name, auto, date, ttn_id без изменений.


4. Что не менялось
------------------
- URL и метод GET
- отсутствие обязательной JWT-авторизации
- формат date (YYYY-MM-DD)
- логика выбора ТТН при создании партии (ttn_id)


Как подтянуть изменения на тестовый сервер
==========================================
Репозиторий на сервере: D:\Program Files\PinskGNS
Ветка: develop
Клиентам: http://gns-gas:8080  (или IP сервера :8080)

На сервере (PowerShell от администратора):

  cd "D:\Program Files\PinskGNS"
  git fetch origin
  git checkout develop
  git pull origin develop

  uv sync
  .\.venv\Scripts\python.exe GNS\manage.py migrate
  .\.venv\Scripts\python.exe GNS\manage.py collectstatic --noinput

Затем перезапустить службы NSSM:
  - django (Daphne)
  - celery
  - celery beat

Проверка: Swagger
  http://gns-gas:8080/api/swagger/
В схеме GET /api/ttn/miriada/current/ должны быть operation_name и status.

Мобильному клиенту достаточно обновить разбор ответа этого эндпоинта
после деплоя сервера.
